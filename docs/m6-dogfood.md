# ctxpack M6 — Relay 真实交接试用协议

M6 是产品验收实验，不先增加代码。Codex 在本机 Relay 的隔离检出中使用 M5 CLI，依据已有任务、报告与 Git 证据填写最小 `.ctxpack/` 状态并运行 `capture` 和四种 handoff；不改变 Relay 的主工作区，不推送、发布或运行具有外部副作用的 Relay 操作。Relay 当前没有 Git 远端，因此此阶段不向 Devin Cloud 上传 Relay 源码或本机资料。若实验发现 ctxpack 缺陷，由 Codex整理可复现反馈，再单独交给 Devin 修复 ctxpack 产品代码。

选择一项真实、尚未完成且适合只读判断的 Relay 安全任务。先核对当前源文件、报告和测试记录，明确事实与未验证边界；不得把历史通过的测试写成当前全绿。handoff 的目标、进度、已失败路线、障碍、下一步、验证与相关文件都须能追溯到当前检出或带日期报告；不录入凭据、私人资料或文件正文。生成前后扫描 `.ctxpack/`，确保只有预期的项目状态；不把它提交到 Relay。

做两个独立、同题、只读的接续尝试：handoff 组只读生成的交接文档后回答“目标、当前状态、阻塞、下一步、安全禁区”，基线组从相同 Relay 检出自行检索。记录首次给出正确下一步所需时间、检索/读取次数、重复调查次数、事实遗漏和错误断言。用事先确定的证据清单评判正确性，保留完整命令和计数方法。只对本次样本计算差异，不把单次结果称作通用性能提升；PROJECT.md 提出的首次有效行动时间降低 ≥50%、重复调查调用降低 ≥30% 属于目标门槛，需显示本次是否达到。

完成标准：四种输出可生成、确定性且 `.ctxpack/` 内容不变；至少一种输出在接续尝试中能准确解释任务和安全边界；完成同题基线对照并记录实际数字、证据与局限。若关键事实遗漏、误导或预算裁剪使接续不安全，M6 标记失败并由 Devin 修复后复验。M6 验收结果写入 DELIVERY；完成后再启动 AgentLens M0。
