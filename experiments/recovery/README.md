当前执行器为协议v2：阈值题明确禁止提高用户阈值，准备阶段违例单列，恢复阶段独享8次读取预算并使用独立计时。用 `node --test experiments/recovery/protocol.check.mjs` 验证阶段预算边界。2026-10-03首批45样本属于v1，保留原判定，不用v2重评分；v2尚未开展新的模型采样。

这是五个合成、只读恢复诊断任务，不测代码实施、真实采用或整体开发效率。三组使用相同事实、文件、模型/effort、沙箱、8次只读工具预算和120秒恢复时限；唯一有意变化是交接格式：手写笔记、真实宿主原生压缩、ctxpack实际CLI输出。手写笔记是维护者编写的固定笔记，不冒充用户现场笔记。

先构建源码，再运行 `node experiments/recovery/run.mjs --codex <已验证的桌面CLI绝对路径>`。默认每任务每组3次，45个样本；`--smoke`仅验证首任务三组各一次，不纳入正式结果。输出到新的临时目录，保留全部样本及失败，不删除失败后挑最好成绩。模型固定gpt-6.1-sol/medium；不登录、不改全局配置、不关闭沙箱。该执行器面向已验证的Windows unelevated只读沙箱。

原生组先接收同一事实，真实调用`thread/compact/start`，必须观察contextCompaction完成；人工和ctxpack组开新线程接收各自交接。公共原始事实文件对三组均可读取。所有当前代码/输入文件必须实际读取后再答，历史笔记不能替代当前证据。工具只能返回固定夹具内容，不接受任意文件系统路径；模型使用其他工具的样本标为协议违例，不当有效成绩。

记录每次读取、重复读取、历史笔记重读、越界请求、最终答案、恢复用时、首次读到所需当前文件的用时及原生压缩事件。首个有效读取是窄代理指标，不等于完成任务；输入/输出token由宿主通知原样保留，不强行填0。按任务、组分别报告总数、无效/超时数、有效样本中位数与正确数，失败不丢弃；不比较剔除失败后更漂亮的中位数而隐去成功率。正确性同时检查行动选项与当前证据字段，包含历史计划与最新源码冲突的题。工具预算和统一恢复截止时间相同，不声称严格相等的模型token消费。

正式计时顺序执行三组，并在重复轮次中轮换组序，避免原生组准备期间其他组已经完成造成负载不均。这些题刻意小而可检查；若三组都成功、差异不稳定或ctxpack更慢，应如实报告无收益证据。不能由此证明长期使用价值或完成真实开发任务的C2采用门槛。原生压缩准备耗时另记，不混进恢复阶段；夹具与ctxpack渲染准备耗时一并记录，未测人工编写笔记耗时。涉及网络的仅官方Codex模型请求，材料全部合成，不上传真实仓库或秘密。
