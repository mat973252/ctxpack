# 固定五题的重复对照协议

协议6，2026-10-03。五题与镜像沿用`historical-case.mjs`及已有冻结清单，不改题目、参考实现或验收断言。
这里测量固定历史缺陷任务在三种同源交接输入下的恢复行为，不代表随机工程任务或独立开发者采用。
前三组pilot及更早协议结果不纳入本批次。

## 批次与执行

五题按markdown-text、ctx-fences、lens-wal、relay-clock、permit-proxy排列，重复三轮。
每题每轮依次运行manual/native/ctxpack的轮转排列，起点为`(题序 + 重复序 - 1) % 3`；
同题的每个条件在三轮中各占一次第一、第二、第三位置，总计45个槽位。按编号顺序执行，不并发计时。
manual为维护者固定格式笔记，native为同线程真实准备/压缩，ctxpack为实际本地CLI渲染，完整事实相同。

`sampling-plan.mjs`生成不可覆盖的JSON清单，冻结15份执行/协议文件、CLI构建、package/锁文件、Node/Codex二进制hash、
Codex0.160.0/Java21/Python版本、实际TypeScript解析器hash及五题三组输入hash。模型固定gpt-6.1-sol，effort medium且拒绝模型回退。
模型收到的工具和权限、准备120秒、恢复480秒及24读/4改/4测预算与pilot相同。审核等待计入恢复预算并单列。
构建/锁文件与版本记录不等于第三方安装依赖的逐字节快照；容器镜像与材料另由已有验证器精确核对。

创建前使用已核实的Node和Java21，并保持这些执行文件/构建不变。以下路径由操作者替换为新的控制目录：

```text
node experiments/recovery/sampling-plan.mjs --id historical-20261003-v1 --codex CODEX_EXE --out NEW_BATCH/plan.json
node experiments/recovery/run-real-smoke.mjs --plan NEW_BATCH/plan.json --plan-sha256 PRINTED_SHA256 --slot PRINTED_SLOT_ID --codex CODEX_EXE
```

槽位编号读取计划的slots，不能另传id/condition/image覆盖计划。入口先核对计划SHA与当前运行文件，再原子创建槽位目录。
认领后立即保留claim，所有初始化/准备/模型/测试/复验/清理结果写入该槽位，不覆盖、不自动释放、不重跑失败槽位。

槽位目录只是控制端证据位置，模型cwd另建于系统临时目录，启动前拒绝Git仓库或祖先AGENTS/AGENTS.override指令文件。
若默认临时目录位于含指令文件的用户目录下，先为本次执行进程设置TEMP/TMP到已检查的仓库外临时目录；
例如本机使用D:\Temp。这个覆盖也用于sampling-plan.check.mjs，不改用户持久环境、原指令或全局Codex配置。
实际模型cwd记录在每次evidence.hostCwd中。路径检查失败属于初始化失败，不能跳过检查继续采样。
不得让模型继承控制仓库指令；记忆/插件隔离仍由受限宿主核对。计划副本写入属于初始化try范围，失败尽量留下固定原因；
存储本身不可写时无法保证落盘，仍按只有claim/不完整证据处理，不伪造终态。
上一槽位存在匹配的终态completion后才能启动下一槽位；候选仍须主指导亲读完整源码、按SHA准许测试并复核最终diff。
`formalSample=true`只代表预注册的一次尝试，不代表有效、通过或可用于性能比较。

进程异常退出可能只留下claim或部分证据。文件存在不证明进程仍在运行；先核实原实际handle/进程。
确认终态或handle缺失后，主指导才能补写带原因/时间的interrupted终态记录，保留原件且不得重用槽位。
观察超时不触发重启。源文件、模型、材料或评分需改变时另建批次，并报告旧批次的全部尝试及停止原因；
不能只补跑落后的条件。计划错配或版本变化在认领前拒绝，单列为启动预检失败，不冒充一次模型尝试。

## 预先定义的观察量

- 首次有效行动的操作性定义：在恢复预算内成功完成读取该题指定源码或回归文件，且工具后的完整性检查通过。
  记录调用序号、路径及开始/完成相对毫秒；从恢复提示提交时计时。没有该动作记null，不记0。
  它不证明理解正确、决策保留或后续修复正确。
- 同时保留准备/恢复时间、审核等待及工具总数。读取中同一路径第二次及以后为重复读取；它可能是合理复核，不能直接称浪费。
- 错误观察分别为拒绝调用/宿主协议违规、基线测试非零退出、候选测试非零退出以及最终验收失败。
  非零测试退出仍可能是工具成功返回的有用反馈，不直接算成越权或错误意图。原始调用和每版候选hash保留。
- 成功需要同一最终候选的regression/check通过、宿主/材料/清理核验、新容器完整用例身份与总数通过，
  以及主指导最终源码/diff审阅。脚本的`verified_pending_source_review`不能独立视为全部验收。
- 失败保存阶段、固定错误类别、已观察耗时及调用；清理或证据写入失败不得抹掉原始失败原因。
  不记录未知环境异常的自由文本到汇总，不把缺失调用/用量补为零。

## 汇总与结论边界

先按45个预定槽位逐一列出未开始、未取得终态、失败、待审阅和已验收；总分母始终保留。
对每个任务×条件分别报告计划/尝试/终态/有效/通过数量，再给首次读取、重复读取与恢复耗时的中位数及实际分母。
协议或上下文隔离失败的原始行仍展示，但不进入有效样本中位数；任务失败而协议有效的观测仍保留，
无动作/无耗时用null并单列，不用成功样本筛选隐藏失败。不能把不同仓库的3次小样本混成独立总体。
墙钟结果受其他本机负载及人工审核影响，原始耗时和审核等待分别列出；相减不是自主执行速度的因果估计。

本批次不含完整先前失败方案轨迹，不能验证“已失败方案重复尝试率接近0”；测试约束通过也不等于真实长会话设计决策零遗漏。
两个ctxpack题共享历史仓库，Relay题是测试辅助维护。样本少、没有独立人类笔记作者、模型与任务范围固定，
即使观察到差异也不宣称普遍性能提升或独立采用。若无法支持优于简单笔记的结论，如实报告，不通过扩第二宿主绕开结果。
